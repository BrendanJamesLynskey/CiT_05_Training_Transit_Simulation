# Compute in Transit 05 — Training Transit, Simulated

Does the fixed-band experiment's convergence result turn into wall-clock time and energy, and where would a photonic link module (arXiv:2608.21536) that computes the band in transit help? A SimPy model of eight workers in one or more data centres says: top-k is the fastest to the target loss on every topology simulated; with the optical transform charged against its compute budget the module is the bottleneck; a pluggable never breaks even with AdamW or top-k; and summing the band at the switch gains only on slow WANs (E′ beats AdamW below 1.57 GB/s with the optics run's single-seed steps, 0.83 GB/s with the exact band's), where the same summation done by the GPUs, with no module, gains more. The deck shows the model, the six variants and their wire bytes, the module as a link kernel (interactive stage times), time to target, hot spots and queueing on a shared WAN, break-even against WAN bandwidth (an interactive curve whose recorded points and crossings equal results.md), module GFLOP/s, ENOB and bit planes, energy, labelled extrapolations, and what it means for a link module.

Topics: SimPy model, Link kernel, Time to target loss, Hot spots, Break-even, In-switch summing.
